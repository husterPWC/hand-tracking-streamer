============================================================
一、阶段目标
============================================================

本阶段的核心目标不是直接开始 UniDexGrasp，而是先解决一个更基础、但决定后续 Sim-to-Real 是否成立的问题：

1. 真正接通 LinkerHand L20 Lite 右手；
2. 明确 LinkerBot SDK 的 10 个控制通道分别对应真机什么运动；
3. 验证 MuJoCo 中构建的 “10 个主动自由度 + mimic 从动关节” 是否符合真机实际控制结构；
4. 明确真机 SDK 10-D 与 MuJoCo 10-D 的通道顺序及正负方向；
5. 用真机和 MuJoCo 同时执行相同动作、相同标准姿态，直接进行 Sim–Real 对照；
6. 最终形成统一的 l20lite_joint_mapping.py，作为后续 UniDexGrasp → L20Lite → MuJoCo / 真机的共同接口。

最终结果：
本阶段全部验证通过。当前 L20Lite MuJoCo 10-D + mimic 模型可以作为真机控制模型继续用于后续抓取重定向和 Sim-to-Real。

============================================================
三、真机 CAN 接入
============================================================

使用的硬件接口为 PCAN USB，Linux 下表现为 SocketCAN：

    can0

PCAN 设备驱动可识别为：

    pcan_usb

L20Lite 使用 CAN 1 Mbps。

每次系统启动后，如 can0 尚未配置，可执行：

    sudo ip link set can0 down 2>/dev/null || true
    sudo ip link set can0 type can bitrate 1000000 restart-ms 100
    sudo ip link set can0 txqueuelen 1024
    sudo ip link set can0 up

检查：

    ip -details link show can0

正常状态应包含：

    can0 UP
    state ERROR-ACTIVE
    bitrate 1000000

can-utils 已安装，可使用：

    which candump

正常路径：

    /usr/bin/candump

如 apt/dpkg 中途被打断，可恢复：

    sudo dpkg --configure -a
    sudo apt -f install

============================================================
七、真机 10-D 每个通道的实际运动方向
============================================================

我们没有依赖名字猜测，而是逐个通道在真机上实际运动确认。

------------------------------------------------------------
1. 四指 flex
------------------------------------------------------------

[2] index_flex
    数值降低 -> 食指更加弯曲
    数值升高 -> 食指伸直

并且真机实际观察到：
当 index_flex 改变时，食指 MCP、PIP、DIP 三段一起联动。

这说明真机控制结构确实不是 20 个完全独立关节，而是：
主动低维控制 + 机械耦合。

[3] middle_flex
    数值降低 -> 中指更加弯曲
    数值升高 -> 中指伸直

[4] ring_flex
    数值降低 -> 无名指更加弯曲
    数值升高 -> 无名指伸直

[5] pinky_flex
    数值降低 -> 小指更加弯曲
    数值升高 -> 小指伸直

因此四个 flex 通道统一规律：

    Real SDK flex ↓ = finger flexion ↑


------------------------------------------------------------
2. 三个 ABD / lateral 通道
------------------------------------------------------------

[6] index_abd
    数值增加 -> 食指远离中指
    数值降低 -> 食指靠近中指

[7] ring_abd
    数值增加 -> 无名指远离中指
    数值降低 -> 无名指靠近中指

[8] pinky_abd
    数值增加 -> 小指远离无名指
    数值降低 -> 小指靠近无名指

因此三个 ABD 通道统一规律：

    Real SDK ABD ↑ = finger spread ↑


------------------------------------------------------------
3. 拇指三个通道
------------------------------------------------------------

[0] thumb_flex
测试例：

    99.22 -> 79.22

观察：

    数值降低 -> 拇指向掌心弯
    数值升高 -> 拇指远离掌心


[1] thumb_abd
测试例：

    48.63 -> 63.63

观察：

    数值增加 -> 拇指靠近食指
    数值降低 -> 拇指远离食指


[9] thumb_yaw
测试例：

    43.92 -> 58.92

观察：

    数值增加 -> 拇指绕自身方向顺时针旋转
    数值降低 -> 拇指逆时针旋转

============================================================
十、MuJoCo mimic 机械耦合
============================================================

当前 MuJoCo 没有把 PIP/DIP 等从动关节再设置 actuator，
而是使用 MuJoCo equality 实现 URDF mimic：

    q_child = multiplier * q_parent + offset

典型关系：

拇指：

    thumb_mcp = 1.38 * thumb_cmc_pitch
    thumb_ip  = 1.49 * thumb_cmc_pitch

食指：

    index_pip = 1.30 * index_mcp_pitch
    index_dip = 0.46 * index_mcp_pitch

中指：

    middle_pip = 1.30 * middle_mcp_pitch
    middle_dip = 0.46 * middle_mcp_pitch

右手当前生成 XML 中：

    ring_pip  = 1.34 * ring_mcp_pitch
    ring_dip  = 0.46 * ring_mcp_pitch

    pinky_pip = 1.34 * pinky_mcp_pitch
    pinky_dip = 0.46 * pinky_mcp_pitch

注意：
这正是我们从官方 URDF mimic 信息转换到 MuJoCo equality 后得到的模型。

在动态 demo 中实际验证过，例如食指：

    MCP ≈ 1.357 rad
    PIP ≈ 1.764 rad
    DIP ≈ 0.624 rad

并得到：

    PIP / MCP ≈ 1.300
    DIP / MCP ≈ 0.460


============================================================
十一、为什么最初拇指映射看起来“不对”
============================================================

早期进行单关节 MuJoCo 测试时，我们曾观察到：

    thumb_cmc_pitch
    thumb_cmc_yaw
    thumb_cmc_roll

在全零或不同参考姿态下，其肉眼表现似乎和真实 SDK 的
thumb_flex / thumb_abd / thumb_yaw 名字不能直接对应。

这并不是最终的映射错误。

根本原因是：

拇指三个 CMC DoF 是串联运动链。

即：

    thumb_cmc_roll
        ↓
    thumb_cmc_yaw
        ↓
    thumb_cmc_pitch
        ↓
    thumb_mcp
        ↓
    thumb_ip

因此同一个根部关节在不同 pitch/yaw/roll 基准姿态下，
其末端表现会明显不同。

早期测试：
真机是在当前实际姿态附近做扰动，
MuJoCo 却在另外两个拇指 DoF 接近 0 的姿态做扰动。

两边 baseline 不一致，因此肉眼运动表现不能直接比较。


============================================================
十二、Matched-Baseline 拇指验证
============================================================

真机测试时参考姿态大约：

    thumb_flex = 99.22
    thumb_abd  = 48.63
    thumb_yaw  = 43.92

随后建立 MuJoCo matched-baseline，在近似对应姿态下，
分别扰动：

    thumb_cmc_pitch
    thumb_cmc_yaw
    thumb_cmc_roll

最终观察：

MuJoCo thumb_cmc_pitch 增加：
    -> 拇指朝掌心

MuJoCo thumb_cmc_yaw 增加：
    -> 拇指远离食指

MuJoCo thumb_cmc_roll 增加：
    -> 拇指逆时针旋转

与真机相比：

Real thumb_flex 减少：
    -> 朝掌心

Real thumb_abd 增加：
    -> 靠近食指

Real thumb_yaw 增加：
    -> 顺时针

因此最终证明：
三个拇指 semantic DoF 仍然是 1:1 对应，
不需要 3x3 混合映射，只需要处理 polarity。

============================================================
二十二、对 UniDexGrasp 后续工作的意义
============================================================

现在后续抓取不应该优化完整 20-D 关节角，
而应该始终围绕真实 L20Lite 可以执行的：

    q_L20Lite ∈ R^10

展开。

后续正式路线：

    UniDexGrasp
        ↓
    ShadowHand grasp
        ↓
    Official L20 Adapter
        ↓
    L20 teacher grasp
        ↓
    L20Lite Retargeter
        ↓
    L20Lite semantic 10-D
        ↓
    ┌─────────────────────┐
    │                     │
    ↓                     ↓
    MuJoCo                 Real L20Lite
    ↓                      ↓
    active DoF             LinkerBot SDK
    ↓                      ↓
    mimic equality         mechanical coupling
    ↓                      ↓
    full hand pose         full hand pose


最关键的是：

Retargeter 最终只需要输出一条 L20Lite 可执行的 10-D command。

同一个抓取 command 可以：

1. 先在 MuJoCo 中运行；
2. 检查接触、穿透、碰撞、抓取稳定性；
3. 通过后经过 l20lite_joint_mapping.py；
4. 直接转换为真机 SDK command；
5. 在真实 L20Lite 上执行。

因此后续真正的核心问题已经从：

    “MuJoCo 的 L20Lite 和真机到底是不是一样？”

转变成：

    “如何把 UniDexGrasp / L20 teacher grasp
     最优地重定向成 L20Lite 的 10-D 可执行抓取？”

这就是下一阶段 L20Lite Retargeter 的正式研究问题。
